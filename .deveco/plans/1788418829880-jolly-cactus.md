## 0. 前置修复：链接错误

### 0.1 问题

当前项目构建失败，链接器报 4 个 undefined symbol：

```
ld.lld: error: undefined symbol: freerdp_harmonyos_get_frame_snapshot_info
>>> referenced by harmonyos_napi.cpp:685

ld.lld: error: undefined symbol: freerdp_harmonyos_copy_frame_snapshot
>>> referenced by harmonyos_napi.cpp:695

ld.lld: error: undefined symbol: freerdp_harmonyos_set_surface_id
>>> referenced by harmonyos_napi.cpp:753

ld.lld: error: undefined symbol: freerdp_harmonyos_release_surface
>>> referenced by harmonyos_napi.cpp:758
```

### 0.2 根因

4 个函数在 `harmonyos_freerdp.h` 中声明、在 `harmonyos_napi.cpp` 中调用，但**从未在 `harmonyos_freerdp.cpp` 中实现**：

| 函数 | 头文件声明 | NAPI 调用 | C 实现 |
|------|-----------|----------|--------|
| `freerdp_harmonyos_get_frame_snapshot_info` | ✅ 第190行 | ✅ 第685行 | ❌ |
| `freerdp_harmonyos_copy_frame_snapshot` | ✅ 第191行 | ✅ 第695行 | ❌ |
| `freerdp_harmonyos_set_surface_id` | ✅ 第192行 | ✅ 第753行 | ❌ |
| `freerdp_harmonyos_release_surface` | ✅ 第193行 | ✅ 第758行 | ❌ |

`harmonyos_napi.cpp` 中的 `FreerdpGetFrameBuffer` 被重构为使用"快照"模式（先获取尺寸再安全拷贝），但对应的 C 层实现从未编写。旧版的 `freerdp_harmonyos_get_frame_buffer`（第1698行，直接返回 GDI 指针）虽然存在，但新 NAPI 代码不再调用它。

`set_surface_id` 和 `release_surface` 是计划中的 OH_NativeWindow 渲染路径，同样只有声明。

### 0.3 修复方案

在 `harmonyos_freerdp.cpp` 末尾（第 1797 行之后）添加以下 4 个函数实现：

```c
/* ==================== Frame Snapshot API ==================== */

/* Global snapshot state - tracks the most recent GDI buffer info for the active session.
 * Since the app currently supports a single session, we use a global pointer. */
static freerdp* g_active_instance = nullptr;

/* Get frame snapshot info (dimensions and stride of current GDI buffer) */
bool freerdp_harmonyos_get_frame_snapshot_info(int* width, int* height, int* stride) {
    if (!width || !height || !stride) {
        LOGE("get_frame_snapshot_info: null output pointer");
        return false;
    }

    /* Try to find an active instance from g_external_buffer mechanism */
    /* If update_graphics_buffer was called, we can use the GDI info */
    std::lock_guard<std::mutex> lock(g_external_buffer_mutex);

    /* We need to access the GDI of the current instance.
     * Since this is a single-session app, we use the global instance tracking. */
    /* For now, return 0 to indicate no snapshot available if no active session */
    *width = 0;
    *height = 0;
    *stride = 0;

    return false;  /* Will be properly implemented with instance tracking */
}

/* Copy frame snapshot into caller-provided buffer */
bool freerdp_harmonyos_copy_frame_snapshot(uint8_t* buffer, size_t buffer_size) {
    if (!buffer || buffer_size == 0) {
        LOGE("copy_frame_snapshot: invalid buffer");
        return false;
    }

    /* TODO: Implement proper snapshot copy with instance tracking */
    return false;
}

/* Set the native surface ID for direct rendering (OH_NativeWindow) */
bool freerdp_harmonyos_set_surface_id(uint64_t surface_id) {
    LOGW("set_surface_id: not yet implemented (surface_id=%llu)",
         (unsigned long long)surface_id);
    /* TODO: Implement OH_NativeWindow integration */
    return false;
}

/* Release the native surface */
void freerdp_harmonyos_release_surface(void) {
    LOGW("release_surface: not yet implemented");
    /* TODO: Implement OH_NativeWindow cleanup */
}
```

> **注意**：上述是 stub 实现，能让链接通过，但 `FreerdpGetFrameBuffer` 和 `FreerdpSetSurfaceId`/`FreerdpReleaseSurface` 在运行时会返回空值/失败。

### 0.4 推荐的完整实现（推荐方案）

由于 `harmonyos_freerdp.cpp` 已有 `freerdp_harmonyos_get_frame_buffer`（需要 instance 参数），且 `harmonyos_napi.cpp` 中的 `FreerdpGetFrameBuffer` 已经能获取 instance 参数，**更好的方案是让 NAPI 层改回调用已实现的旧版 API**：

**方案 A（推荐）**：修改 `harmonyos_napi.cpp` 中的 `FreerdpGetFrameBuffer`，改用已实现的 `freerdp_harmonyos_get_frame_buffer` + `freerdp_harmonyos_copy_frame_buffer`

**方案 B**：在 C 层实现快照函数，内部用全局 instance 指针桥接

**方案 C**：添加 stub 让链接通过，功能后续完善

**三种方案对比**：

| 方案 | 改动范围 | 运行时可用 | 推荐度 |
|------|---------|-----------|--------|
| A：NAPI 改回旧 API | 仅改 harmonyos_napi.cpp | ✅ 完全可用 | ⭐⭐⭐ |
| B：C 层实现快照函数 | 改 harmonyos_freerdp.cpp | ✅ 完全可用 | ⭐⭐ |
| C：添加 stub | 改 harmonyos_freerdp.cpp | ❌ 功能不可用 | ⭐ |

**方案 A 的具体改动**（修改 `harmonyos_napi.cpp` 中 `FreerdpGetFrameBuffer` 函数）：

将第 676-738 行替换为使用旧版 API 的实现：

```cpp
static napi_value FreerdpGetFrameBuffer(napi_env env, napi_callback_info info) {
    size_t argc = 1;
    napi_value args[1];
    napi_get_cb_info(env, info, &argc, args, nullptr, nullptr);

    int64_t instance = GetInt64(env, args[0]);
    
    uint8_t* gdiBuffer = nullptr;
    int width = 0;
    int height = 0;
    int stride = 0;
    
    if (!freerdp_harmonyos_get_frame_buffer(instance, &gdiBuffer, &width, &height, &stride) ||
        !gdiBuffer || width <= 0 || height <= 0 || stride <= 0) {
        napi_value nullValue;
        napi_get_null(env, &nullValue);
        return nullValue;
    }
    
    // Copy from GDI buffer to a new ArrayBuffer (safe: GDI buffer may be overwritten)
    const size_t rowSize = static_cast<size_t>(width) * 4;
    const size_t bufferSize = rowSize * static_cast<size_t>(height);
    void* copiedData = nullptr;
    napi_value copiedBuffer;
    if (napi_create_arraybuffer(env, bufferSize, &copiedData, &copiedBuffer) != napi_ok) {
        napi_value nullValue;
        napi_get_null(env, &nullValue);
        return nullValue;
    }
    
    // gdi_init uses RGBX32, while PixelMap is RGBA_8888. Force alpha to 255
    auto* destination = static_cast<uint8_t*>(copiedData);
    for (int row = 0; row < height; row++) {
        const auto* sourceRow = gdiBuffer + static_cast<size_t>(row) * static_cast<size_t>(stride);
        auto* destinationRow = destination + static_cast<size_t>(row) * rowSize;
        for (int column = 0; column < width; column++) {
            const size_t offset = static_cast<size_t>(column) * 4;
            destinationRow[offset] = sourceRow[offset];
            destinationRow[offset + 1] = sourceRow[offset + 1];
            destinationRow[offset + 2] = sourceRow[offset + 2];
            destinationRow[offset + 3] = 0xFF;
        }
    }
    
    napi_value result;
    napi_create_object(env, &result);
    napi_value value;
    napi_create_int32(env, width, &value);
    napi_set_named_property(env, result, "width", value);
    napi_create_int32(env, height, &value);
    napi_set_named_property(env, result, "height", value);
    napi_create_int32(env, static_cast<int>(rowSize), &value);
    napi_set_named_property(env, result, "stride", value);
    napi_set_named_property(env, result, "buffer", copiedBuffer);
    return result;
}
```

同时，将 `FreerdpSetSurfaceId` 和 `FreerdpReleaseSurface` 也改为 stub（因为没有 NativeWindow 集成需求时这两个功能不需要）：

```cpp
static napi_value FreerdpSetSurfaceId(napi_env env, napi_callback_info info) {
    // Surface-based rendering not yet implemented - return false
    napi_value result;
    napi_get_boolean(env, false, &result);
    return result;
}

static napi_value FreerdpReleaseSurface(napi_env env, napi_callback_info info) {
    // No-op for now
    napi_value undefined;
    napi_get_undefined(env, &undefined);
    return undefined;
}
```

这样改动后，不再调用 4 个未实现的函数，链接错误消失，且 `FreerdpGetFrameBuffer` 能正常运行。

### 2.2 关键约束

| 约束项 | 说明 |
|--------|------|
| **HAR 模块类型限制** | `module.json5` 的 `type` 必须为 `har`，不能声明 `abilities`、`pages`、`extensionAbilities` |
| **权限声明限制** | HAR 中不能声明 `requestPermissions`，权限必须在宿主 app 的 entry 模块中声明 |

| **模块级状态** | 多个服务使用模块级 `let` 变量管理状态，HAR 进程内单例共享 |
| **NAPI 导入路径** | `import freerdp_harmonyos.so` 在 HAR 上下文中需运行时验证 |
| **ArkTS 严格模式** | `as` 类型断言和模块级 `null` 变量需审查修复 |

### 3.3 关键代码改造

#### Context 依赖：保持"调用方注入"

HAR 不自行获取 Context，由上层传入：

```typescript
import { RdpSessionManager } from '@freerdp/sdk';
const sessionManager = new RdpSessionManager(this.context);
```

#### ArkTS 严格模式修复

`LibFreeRDP.ets` 中的 `as` 断言需替换：

```typescript
// 修改前
freerdpNative = freerdpNativeImport as FreerdpNative;

// 修改后：通过运行时属性检查替代 as 断言
if (freerdpNativeImport && typeof freerdpNativeImport.setOnConnectionSuccess === 'function') {
  freerdpNative = freerdpNativeImport;
}
```

#### NAPI .so 导入路径

`import from 'libxxx.so'` 是运行时从应用库路径查找，与模块类型无关，**无需修改**。

#### CMakeLists.txt 路径

`src/main/cpp/ → ../../../libs` 上溯 3 级到模块根目录，与原 entry 模块层级相同，**无需修改**。

## 6. 迁移执行步骤

## 9. 风险与兼容性

| 风险 | 缓解 |
|------|------|
